# Organizer PDF

A Windows desktop toolkit for organizing school materials and performing everyday PDF work: assemble, split, extract and optimize documents, all locally and without touching the original files.

## Overview

Organizer PDF started as a tool for teachers who receive large PDFs made of many separate materials and need to separate, name and export each one. It has since grown into a general PDF workbench with four modules, a local history and persistent work-in-progress recovery.

Design principles:

- **Local first.** Reading, organizing, assembling, splitting, extracting, optimizing, history and presets work offline. The optional AI step runs only with an explicit key and per-analysis consent.
- **Originals are never modified.** Every operation works on a verified private copy identified by SHA-256, and results are published without overwriting existing files.
- **Verified output.** Before a result is published it is checked against its source (page count, order, size, rotation, text and, where applicable, rendered appearance).

## Key Features

- **Pedagogical organization.** Open a large PDF, analyze it locally (text, rules and OCR), review suggested material boundaries, then create, edit, merge, split, rename, confirm and export materials.
- **Multi-source assembly.** Build a new PDF from pages of several files, in the final order, with drag and drop support.
- **Page editing.** Reorder, duplicate, rotate 90°, remove and undo (up to 200 steps), with a preview of the final result.
- **Split and extract.** Split by ranges, by blocks of N pages or one page per file; extract an ordered selection into one file, one file per page or one per contiguous run.
- **Optimization.** Three explicit profiles (lossless, balanced, compact). A result that is not smaller than the original is not kept unless requested.
- **Batch operations.** Queued, serial processing with cancellation checks between steps and files.
- **History and presets.** Each operation records its outcome (pages, outputs, destination, sources with SHA-256, warnings). Repeating an operation or applying a preset only fills the panel; nothing runs without confirmation.
- **Persistence and recovery.** Assembly work is autosaved as a draft and offered for recovery after an unexpected exit; each source is revalidated by existence, SHA-256 and page count before reopening.
- **Native Windows interface** built with PySide6.

## Application Modules

| Module | Purpose |
|---|---|
| Organize Materials | Analyze a large PDF, review boundaries, confirm and export individual materials. |
| Assemble PDF | Compose a new document from pages of one or more PDFs. |
| Split, Extract and Optimize | Three independent operations sharing the same verified work pipeline. |
| History and Presets | Review past operations, reopen configurations, repeat operations, manage presets. |

## Architecture Overview

```text
 UI (PySide6)       main window · assembler · tools · history · dialogs
        │
 Services           compose · batch · optimize · export · analysis pipeline
        │
 Domain models      composition and range planning (no Qt, no PDF I/O)
        │
 Stores (SQLite)    documents and groups · assemblies · history and presets
        │
 PDF layer          verified private copies · exclusive publish · PyMuPDF
```

- The composition and range-planning models are independent of Qt and of PDF I/O, which keeps them directly testable.
- All writing goes through one worker pipeline and one verified-copy mechanism; there is no second way to write a PDF.
- User data lives in a per-user folder under `%LOCALAPPDATA%`. PDF contents are not copied into the database; assemblies store path, SHA-256 and page count of each source. The database is not encrypted at rest.
- Passwords, tokens and credentials are not written to history or presets.

## Technical Validation

Phase 7A (isolated technical validation, 2026-11-11) ended with **936 tests passed, 8 skipped and zero failures** (944 distinct cases) in an isolated environment on Windows 11 with Python 3.14.10, PyMuPDF 1.28.2 and PySide6 6.11.2. The two tests that depend on private PDFs are among the skipped ones. All input PDFs were generated by the tests.

This is an automated validation only. **Functional validation on Windows (Phase 7B) has not been completed.**

## Current Project Status

- Functional development of the planned modules is complete (through Phase 6.7).
- Automated technical validation (Phase 7A) is complete, with the caveats above.
- Windows functional validation is **pending**. The product is **not validated for distribution** and no installer or executable is published.

Known limitations include: no deletion or renaming of saved assemblies in the interface, no import/export of presets, no PDF/A, digital signing or encryption of generated PDFs, and no undo across sessions. Signed, XFA and password-protected documents are handled conservatively (refused or warned, depending on the operation).
